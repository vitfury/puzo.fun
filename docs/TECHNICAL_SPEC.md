### Візуалізація

- **2D інтерактивна карта** з можливістю переміщення (pan) та зумування
- Візуалізація як дерево з нодами та з'єднувальними лініями
- Кожна нода показує:
  - Іконку жанру
  - Назву жанру
  - Статус: заблокований / доступний / пройдений
  - При наведенні: попередній перегляд (short tooltip)
- Історична прив'язка: можливість фільтрувати/сортувати по рокам (опціонально відображати timeline)

### Логіка прогресії

1. **Початок:** Користувач починає з кореневого вузла (наприклад, "Класичний рок")
2. **Відкриття жанру:** 
   - При кліку на доступний жанр відкривається детальна сторінка з:
     - Описом (HTML/Markdown)
     - Вбудованим YouTube Music плейлистом (віджет)
     - Списком треків (отриманих через YouTube API)
     - Полем для коментаря
   - Жанр автоматично вважається "пройденим" при першому відкритті
3. **Розблокування нових жанрів:**
   - Наступного дня (після 6:00 ранку) відкриваються всі дочірні жанри пройденого вузла
   - Якщо користувач пропустив день (не виконав щоденні активності), нові жанри НЕ відкриваються
4. **Повернення:** Користувач може в будь-який час повернутися до пройдених жанрів для перегляду

### Сайд-квести

- **Розблокування:** З'являються після досягнення 3-денного streak виконання щоденних активностей
- **Контент:** Музичні групи/виконавці, які не належать чітко до одного жанру (міксові стилі)
- **Структура:** Аналогічна до основних жанрів (опис, плейліст, коментарі)
- **Відмітка в БД:** Поле `is_side_quest = true` в таблиці `genre_nodes`

### Адмін-панель для музичного дерева

- CRUD жанрів: створення, редагування, видалення вузлів
- Редактор структури дерева:
  - Можливість встановлювати parent_id (зв'язок між жанрами)
  - Візуальний редактор позиції на карті (drag-and-drop)
- Rich-text редактор для опису (підтримка Markdown/HTML)
- Завантаження зображень
- Встановлення координат та років

## 🏃 Інтеграція з Strava

### Дані для збору
- Кількість кроків за день (якщо доступно з активностей типу Walk/Run)

- Спалені калорії
- Час активності (тривалість прогулянок/пробіжок)
- Тип активності (Walk, Run, Hike)

### Технічна реалізація

**OAuth 2.0 через Strava:**
- Authorization endpoint: `https://www.strava.com/oauth/authorize`
- Token endpoint: `https://www.strava.com/oauth/token`
- Required scopes: `activity:read_all`, `profile:read_all`

**API Endpoints для використання:**
- `GET /api/v3/athlete` - профіль атлета
- `GET /api/v3/athlete/activities` - список активностей
- `GET /api/v3/activities/{id}` - деталі активності

### Періодична синхронізація
- Laravel Schedule запускає job кожні 10 хвилин
- Job робить запит до Strava API для кожного користувача
- Отримує активності за поточний день (з 00:00 до поточного часу)
- Агрегує дані: сума дистанцій, калорій, тривалості
- Конвертує дистанцію в кроки (приблизно): 
  - Walk: 1 км ≈ 1300 кроків
  - Run: 1 км ≈ 1200 кроків
  - Hike: 1 км ≈ 1400 кроків
- Оновлює `user_fitness_data` для поточної дати

### Відображення
- В профілі користувача постійно відображаються:
  - Кроки за сьогодні (оновлення кожні 10 хв)
  - Дистанція за сьогодні
  - Калорії за сьогодні
  - Час активності за сьогодні
- Можливість вручну запустити синхронізацію (кнопка "Оновити дані")
- Історія даних доступна для перегляду (графіки за тиждень/місяць)

### Deep Links для запуску активності

**Strava Deep Links:**
Strava підтримує deep links для відкриття додатку:
- `strava://record` - відкриває екран запису нової активності
- На веб-версії можна додати кнопку "Почати прогулянку", яка:
  - На мобільному: відкриває Strava через deep link
  - На десктопі: показує інструкцію користувачу

**Реалізація на frontend:**
```javascript
const startStravaActivity = () => {
  // Спроба відкрити Strava app
  window.location.href = 'strava://record';
  
  // Fallback: якщо app не встановлений, через 2 секунди редірект на web
  setTimeout(() => {
    window.location.href = 'https://www.strava.com/';
  }, 2000);
};
```

### Автоматичне відкриття музичного плейліста

Ідея: коли користувач тисне "Почати прогулянку" на жанрі:
1. Відкривається YouTube Music плейліст (через deep link або web)
2. Одночасно відкривається Strava для запису активності
3. Користувач слухає музику і гуляє, Strava записує активність

**YouTube Music Deep Links:**
- `https://music.youtube.com/playlist?list=PLAYLIST_ID` - відкриває плейліст
- На мобільному автоматично відкриється в додатку YouTube Music (якщо встановлений)

**UX Flow:**
- Користувач на сторінці жанру натискає велику кнопку "🎵 Почати музичну прогулянку"
- Відкривається модальне вікно з інструкціями:
  1. "Зараз відкриється плейліст в YouTube Music"
  2. "Потім відкриється Strava для запису прогулянки"
  3. Кнопка "Погнали!" - запускає обидва deep links
- Після завершення прогулянки, дані автоматично синхронізуються в Melody Ninja

### Webhook від Strava (опціонально, для real-time оновлень)

Strava підтримує webhooks для отримання подій в реальному часі:
- `POST https://melody.ninja/api/webhooks/strava` - endpoint для webhook
- Події: `activity.created`, `activity.updated`
- При отриманні події - негайно оновлюємо дані користувача
- Це дозволить оновлювати дані одразу після завершення активності, без очікування cron job'а

**Налаштування webhook:**
1. Створити subscription через Strava API
2. Вказати callback URL: `https://melody.ninja/api/webhooks/strava`
3. Верифікувати webhook (Strava надсилає challenge)
4. Обробляти події в Laravel controller

## 🔔 Система нотифікацій

### Firebase Cloud Messaging (FCM)

**Технічна реалізація:**

Firebase Cloud Messaging забезпечує надійну доставку push-нотифікацій на iOS та Android через веб-додаток.

**Налаштування:**
1. Створити проект в Firebase Console
2. Додати веб-додаток до проекту Firebase
3. Отримати `firebaseConfig` та Server Key
4. Інтегрувати Firebase SDK в React додаток

**Frontend (React):**
- Встановити `firebase` package
- Ініціалізувати Firebase в додатку
- Запросити дозвіл на нотифікації через `Notification.requestPermission()`
- Отримати FCM token через `getToken()`
- Відправити token на backend для збереження
- Слухати нотифікації через `onMessage()`

**Backend (Laravel):**
- Встановити пакет для роботи з FCM (наприклад, `kreait/firebase-php`)
- Зберігати FCM tokens користувачів в БД
- Відправляти нотифікації через Firebase Admin SDK

**Таблиця `user_fcm_tokens`:**
```
id: bigint
user_id: bigint
token: text (FCM token)
device_type: enum('web', 'ios', 'android')
is_active: boolean
created_at, updated_at
```

**Важливо для iOS:**
- iOS вимагає HTTPS для Service Workers
- Веб-додаток повинен бути доданий на Home Screen для stable роботи push
- Альтернативно: використати PWA (Progressive Web App) для кращої інтеграції

**Важливо для Android:**
- Service Worker для background нотифікацій
- Manifest.json з правильними налаштуваннями
- Іконки нотифікацій (різних розмірів)

### Типи нотифікацій

**Для користувача:**

1. **Щоденне нагадування:**

2. **Нагадування про незавершені активності:**
   - Час: за 2 години до кінця дня (22:00)
   - Текст: "⚠️ У тебе залишилось [N] активностей на сьогодні!"
   - Дія: відкриття додатку на сторінці щоденника

3. **Досягнення нового рівня:**
   - Час: одразу після досягнення
   - Текст: "🎉 Вітаю! Ти досяг нового рівня: [назва титулу]!"
   - Дія: відкриття профілю

4. **Розблокування сайд-квесту:**

   - Дія: відкриття сайд-квесту

5. **Нагорода за streak:**
   - Час: о 6:00 після досягнення milestone (7, 14, 30 днів)

   - Дія: відкриття профілю

6. **Новий челендж:**
   - Час: при активації челенджу адміном

   - Час: одразу після виконання
   - Текст: "✅ Челендж '[назва]' виконано! +[X] очок"
   - Дія: відкриття сторінки челенджів

8. **Попередження про калорії:**
   - Час: коли залишилось менше 200 ккал до ліміту

   - Дія: відкриття щоденника харчування

9. **Перевищення ліміту калорій:**
   - Час: одразу після додавання запису, що перевищує ліміт
   - Текст: "🚫 Ліміт калорій перевищено на [X] ккал!"
   - Дія: відкриття щоденника харчування

1. **Звіт про активність користувача:**
   - Час: щодня о 23:00

3. **Попередження про перевищення калорій:**

   - Дія: відкриття щоденника харчування користувача

### Альтернатива: Нотифікації через Strava

Strava не має публічного API для відправки push-нотифікацій користувачам. Однак є workaround:

**Strava Comments/Kudos як нотифікації:**
- Використати Strava API для автоматичного коментування активностей користувача
- Коли брат завершує прогулянку в Strava, через webhook отримуємо подію
- Автоматично залишаємо коментар на його активності:
  - "🎵 Чудова прогулянка! +10 очок в Melody Ninja!"
  - "🔥 3 дні streak! Сайд-квест розблоковано!"
- Користувач отримує стандартну нотифікацію від Strava про новий коментар

**Реалізація:**
- Потрібен додатковий scope: `activity:write`
- API endpoint: `POST /api/v3/activities/{id}/comments`
- Текст коментаря формується на backend в залежності від досягнення

**Плюси:**
- Не потрібна складна інфраструктура для push
- Користувач точно побачить нотифікацію (нативна Strava)
- Додаткова мотивація (публічні коментарі можуть бачити друзі в Strava)

**Мінуси:**
- Обмежена кількість типів нотифікацій
- Неможливо контролювати час відправки
- Залежність від активності в Strava

### Email нотифікації (fallback)

**Таблиця `user_notification_settings`:**
```
id: bigint
user_id: bigint
fcm_enabled: boolean (дозвіл на FCM push)
email_enabled: boolean
strava_comments_enabled: boolean (дозвіл на коментарі в Strava)
daily_reminder_time: time (час для щоденного нагадування)
daily_summary_enabled: boolean (щоденний звіт на email)
created_at, updated_at
```

**Email типи:**
1. Щоденний звіт (якщо `daily_summary_enabled = true`):
   - Відправляється о 22:00
   - Містить: виконані активності, кроки, калорії, пройдені жанри, баланс очок
   
2. Fallback для критичних подій:
   - Якщо FCM token недійсний або push не доставлено
   - Відправка email замість push

**Налаштування пріоритетів:**
Користувач може вибрати канали для кожного типу нотифікацій:
- Щоденне нагадування: FCM ✓ / Email ☐ / Strava ☐
- Досягнення: FCM ✓ / Email ☐ / Strava ✓
- Челенджі: FCM ✓ / Email ☐ / Strava ☐
- І так далі...

### Laravel реалізація

**Notification класи:**
- `DailyReminderNotification`
- `NewLevelAchievedNotification`
- `SideQuestUnlockedNotification`
- `StreakBonusNotification`
- `ChallengeCompletedNotification`

Кожна нотифікація може мати декілька каналів (via):
```php
public function via($notifiable)
{
    $channels = [];
    
    if ($notifiable->notification_settings->fcm_enabled) {
        $channels[] = 'fcm';
    }
    
    if ($notifiable->notification_settings->email_enabled) {
        $channels[] = 'mail';
    }
    
    if ($notifiable->notification_settings->strava_comments_enabled) {
        $channels[] = 'strava';
    }
    
    return $channels;
}
```

**Custom Channel для Strava:**
Створити `StravaCommentChannel` який надсилає коментарі до останньої активності користувача.

- **Кожні 10 хвилин:** Синхронізація даних з Strava для всіх користувачів
- **Кожні 15 хвилин:** Перевірка та оновлення Strava access tokens (refresh якщо expires)
- **О 6:00 щодня:** Створення щоденних активностей для всіх користувачів
- **О 6:00 щодня:** Розблокування нових жанрів для користувачів, що виконали вчорашні активності
- **О 6:00 щодня:** Оновлення streak для всіх користувачів
- **О 6:00 щодня:** Нарахування бонусних очок за streak milestones
- **Кожну годину:** Перевірка виконання челенджів та нарахування нагород
- **Щодня в час встановлений користувачем:** Відправка щоденного нагадування про прогулянку (FCM push)
- **О 22:00 щодня:** Відправка нагадування про незавершені активності (якщо є)
- **О 23:00 щодня:** Відправка звіту адмінам про активність користувачів (включаючи баланс калорій)
- **О 20:00 щодня:** Перевірка наближення до ліміту калорій та відправка попередження (якщо залишилось <200 ккал)

### Gamification механізми (додаткові ідеї)

**Milestone досягнення:**

```
created_at, updated_at
```

**Таблиця `user_badges`:**
```

earned_at: timestamp
created_at, updated_at
```

## 📝 Примітки для розробника

- Використовувати Laravel Sanctum для API аутентифікації
- Всі дати та час зберігати в UTC, конвертувати на frontend
- Валідація даних на обох рівнях (frontend + backend)
- Логування всіх критичних операцій (нарахування очок, виконання активностей)
- Unit тести для бізнес-логіки (нарахування очок, streak, розблокування жанрів)
- Використовувати Laravel Horizon для моніторингу черг
- Redis для кешування часто запитуваних даних (список жанрів, статистика)
- **Strava API rate limits:** 100 requests per 15 minutes, 1000 requests per day per user - врахувати при синхронізації
- **Firebase:** Для production потрібен платний план (Blaze) для використання Cloud Functions (опціонально)
- **HTTPS обов'язковий:** Service Workers та FCM працюють тільки через HTTPS
- **PWA manifest:** Додати manifest.json для можливості "додати на home screen" на мобільних
- **Service Worker:** Реєстрація в React для offline support та background sync
- Шифрування Strava tokens в БД (Laravel encryption)
- Обробка expired/revoked Strava tokens з автоматичним refresh
- Webhook від Strava має бути захищений (verify signature)
- **Claude API:** Використовувати Claude 3.5 Sonnet для аналізу їжі
- **Claude Vision:** Для аналізу фото їжі використовувати multimodal capabilities
- **Обробка зображень:** Стиснення фото перед відправкою до Claude API (оптимізація розміру)
- **Кешування:** Claude API відповіді можна кешувати для однакових запитів (наприклад, "яблуко")
- **Fallback:** Якщо Claude API недоступний, можна використати локальну базу даних продуктів
- **Камера в браузері:** Використовувати MediaDevices API для доступу до камери
- **Privacy:** Фото їжі зберігати з обмеженим доступом (тільки користувач і адмін)
